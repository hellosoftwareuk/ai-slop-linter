A learned code-quality referee for slop

Your linter passes. Your code still reads badly.

Slop's referee is a transformer trained on 3,226 real refactor commits from 2,226 open-source repositories. It finds the code reviewers would flag, then lets a rewrite through only when the tests pass and the code reads measurably better.

Control column: how often a method prefers the newer version of ordinary bug-fix and feature commits (660 pairs). A quality signal has no reason to; near 50% means it is not just detecting newer or longer code.

Rule engine: slop's file-local debt points on the whole file. Surface statistics: logistic regression on 14 style measures (indentation, line length, nesting, identifier length, branch density). Repositories are split by hash, so no repository contributes to both training and test. Commit messages are noisy labels, so no method should approach 100% here.

How it works

Trained on how developers actually clean up code

Learn from refactor commits

Every commit titled "refactor", "simplify" or "extract helper" is a developer saying the new code is better than the old. We mine aligned before/after windows from CommitPack, strip comments, and split by repository.

Rank the before and after

A 125M-parameter code encoder (UniXcoder) is fine-tuned so the refactored window scores higher than the original. The score is learned, not hand-written, so it catches what no rule names.

Referee every rewrite

Hotspots are ranked across your tree. Any rewrite, from a person or an AI agent, must pass tests, clippy, rustfmt and slop's rules, and must raise the referee score of every region it touched.

It judges, it does not write

Rewrites come from you or your coding agent. The referee decides which ones are worth keeping.

It never checks behaviour

Tests, clippy and slop's proof-checked rules guard behaviour. Untested code gets characterisation tests before it changes.

Local design, not system design

It reads about 50 lines at a time. Dependency cycles, coupling and layering stay with slop's repository graph rules.

Hotspots need a human look

Two of the top six windows in our own repo were false positives: a textbook graph algorithm and raw test fixtures.
